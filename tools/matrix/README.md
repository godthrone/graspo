# `tools/matrix/` — 功能矩阵文档工具链

本目录是功能矩阵文档（`docs/capability-matrix.html`）与其机读形式
（`docs/capability-matrix.data.json`）的**唯一产出与校验通道**。

> ★ **数据文件 `docs/capability-matrix.data.json` 是唯一真相源**（唯一可编辑的源头）；
> `docs/capability-matrix.html` 是它经 `render_matrix.py` **确定性生成的只读派生视图**
> （⛔ 禁止手工编辑、⛔ 禁止「以视图为准回填数据」）。
> 训练配置（`samples/configs/**/*.yaml` 等）以该数据为准派生。

## 产出模型

```
tools/matrix/template.html   （骨架 / 版式 / 定义文字）
docs/capability-matrix.data.json（机读数据：列定义 + 统一口径 + 逐档参数与结果）
        └── render_matrix.py ──► docs/capability-matrix.html（人读正式件）
        └── verify_matrix.py ──► 重新渲染 + 逐字节比对 + 结构/内容/脱敏断言
```

**HTML 不得手工编辑。** 任何修改都必须改「模板」或「数据」，再经 `render_matrix.py` 重新产出；
`verify_matrix.py` 会重新渲染并与在盘 HTML 逐字节比对，任一字节不同即失败，并打印首个差异的
字节偏移 / 行号 / 列号。

> 本文件（`README.md`）承载**作业说明**；正式文档 `docs/capability-matrix.html` 只保留
> **定义与表格**，不含作业过程与决策记录。

## 命令

```bash
# 渲染（唯一允许的 HTML 产出通道）
python3 tools/matrix/render_matrix.py \
    --template tools/matrix/template.html \
    --data docs/capability-matrix.data.json \
    --out docs/capability-matrix.html

# 校验（逐字节比对 + 结构 / 内容 / 脱敏断言）
python3 tools/matrix/verify_matrix.py \
    --template tools/matrix/template.html \
    --data docs/capability-matrix.data.json \
    --html docs/capability-matrix.html

# 三组自证（空数据 PASS / 假数据 PASS / 手改 1 字符 FAIL + 报偏移）
python3 tools/matrix/run_self_proof.py
```

## 文件职责

| 文件 | 职责 |
|---|---|
| `template.html` | 文档骨架、版式与**定义文字**（判据定义 / 参数定义 / 状态定义） |
| `render_matrix.py` | **唯一渲染通道**：模板 + 数据 ⇒ HTML（确定性，不读时钟 / 环境 / 网络） |
| `verify_matrix.py` | 执法：重新渲染 + 逐字节比对 + 手改定位 + 结构 / 内容 / **脱敏**断言 |
| `build_official.py` | 由内部数据生成**脱敏**的正式机读件 `docs/capability-matrix.data.json` |
| `build_data.py` | 由抽取结果构建内部数据（列定义 + 统一口径 + 逐档参数） |
| `extract_params.py` / `extract_spec.py` | 从配置来源抽取逐档参数与规格（内部用） |
| `backfill_matrix.py` | 跑次结果回填：跑次记录 ⇒ 数据 ⇒ 重渲染 ⇒ 校验（增量、失败即停） |
| `run_self_proof.py` | 自证（空数据 / 在盘件 / 假数据 / 手改 1 字符 / 表格之外逐字节不变） |

## 脱敏与「内部字段不进人读视图」（强制）

正式件（HTML 与 data.json）**不得出现**宿主路径、内网地址、机器名、人名、内部节点与内部账号
（宪法 §17.7「矩阵中仍然禁止」；**矩阵落点不适用** §15.4 的放宽），也**不得出现**
内部称谓与内部编排（主席 / 指挥部 / 口径包 / 修正轮 / 第 N 批 / 工位 …）——矩阵的读者是使用者。

三处机核（同源同处，⛔ 不设第二家）：

| 位置 | 机制 |
|---|---|
| `build_official.py` → `HUMAN_VIEW_*_KEYS` + `drop_non_view_fields()` | **显式允许清单**：人读视图不渲染的字段在落盘前逐条剔除并打印（内部权威 `.local/…/matrix-data.json` 一行不动） |
| `build_official.py` → `FORBIDDEN_TERMS` + `forbidden_in_human_view()` | 允许清单之外的**内部术语兜底扫描**，命中即 **fail-closed 拒绝写盘** |
| `build_official.py` → `HUMAN_VIEW_REWRITES` / `human_view_notation()` / `_fix_row_cells()` | 文本级：人称与内部编排 ⇒ 时间口径；`★`/`⛔`/旧编号 ⇒ 自然书写；污染单元格逐格订正 |
| `verify_matrix.py` → ④G / ④M | 逐字节校验时扫「宿主路径 / 内网 / 机器名 / 人名」与「内部术语」 |
| `scan_matrix_leaks.py` | 独立扫描器（**生成物与手写文档同等扫描**，§17.7「扫描不豁免」） |

自检（阳性对照）：
```bash
python3 tools/matrix/build_official.py --human-view-self-test   # 人读视图四件的对抗性输入自检
python3 tools/matrix/build_official.py --self-test              # 脱敏回归（含顺序无关）
```

## 人读件结构与 §17.7 强制项

`docs/capability-matrix.html` 只承载 **① 判据（含口径）② 实验条件 ③ 功能矩阵表**，外加几句读得懂的话；
首屏另有 §17.7 强制的三块：**自动生成声明**、**覆盖度警示（四态计数 + 「尚未验证」档位清单与数量）**、
**承诺边界声明（三点齐备，不得藏进脚注/附录/术语表）**。

- 覆盖度警示由 `render_matrix.py` 的 `build_coverage_warning()` **从 `rows` 现算**：
  ⛔ 不写死任何计数；覆盖度达标（无「尚未验证」）时该块**自动消失**。
- 承诺边界声明块内**另有一行覆盖度门槛注**（`build_boundary()` 现算）：未达门槛时**必须**写明
  「整体承诺尚未生效」，且档数须与 `rows` 一致（`verify_matrix.py` ④P 机核）。
- 标题与摘要**不得**使用能力承诺式措辞；`verify_matrix.py` ④K 在覆盖度未达门槛时对此做机核。

## 设计规则：表格之外一切写死不变，变量全在数据

★ **全文确保只有矩阵随测试与 debug 变化，其他部分写死不变**（主席裁决）。

| 层 | 内容 | 是否随跑次变化 |
|---|---|---|
| `template.html` | 版式、定义（判据定义 / 参数定义 / 状态定义）、表头、边界声明、统一口径块、生成标记 | **写死不变**——不含任何随跑次变化的数值或文案 |
| `capability-matrix.data.json` → `rows` | 档位清单、逐档参数、逐档结论与读数 | **只有这里随跑次变化** |
| `capability-matrix.data.json` → `meta` | 固定文案（边界声明、判定口径、权威性声明、状态词表） | 写死不变；与表格数据**物理分开** |
| `capability-matrix.html` | 由上面两者确定性生成 | 结果 = **只有表格区随数据变化** |

**推论：**

- ⛔ **任何"计数 / 汇总 / 结论性散文"不得出现在表格之外**（它们会随跑次变化，一旦写死就得人工维护）。
- **表格区是唯一随数据变化的部分**；表格之外在数据变化时**逐字节不变**。

**校验方式**：`run_self_proof.py` 的「④ 表格之外逐字节不变」——只改 `rows` 里的数值重新渲染，
断言矩阵表之外的前缀与后缀**逐字节相同**（表格内则确实变化）。

## ★ 与宪法 §17.7 的历史冲突（**已消解，留痕**）

精简轮 1 之前，本项目曾按「只有表格随数据变化」的口径**移除**首屏覆盖度警示与统计
（对应占位符 `{{COVERAGE_WARNING}}` / `{{UNVERIFIED_LIST}}`），与 §17.7「未达覆盖度门槛时**必须**
在首屏写明显式警示，并列出『尚未验证』的档位清单与数量」直接冲突。

**现状（2026-10-16）：该冲突已消解——警示与统计已按 §17.7 恢复**，且做成**数据驱动**：

- `{{COVERAGE_WARNING}}` 由 `build_coverage_warning()` **从 `rows` 现算**（四态计数 + 「尚未验证」档位清单与数量）；
- 覆盖度达标时该块**自动消失**（⛔ 不需人工维护，故当初"写死警示会带来维护负担"的理由已不成立）；
- `verify_matrix.py` ④K 机核警示存在性、计数逐字一致、清单齐全、`data-row-count` 可见性；
- 衍生出 ④P：承诺边界声明块内的**覆盖度门槛注**必须在位且档数与 `rows` 一致。

⛔ 因此本文件**不再**主张任何 §17.7 豁免；如后续需要再次变更该口径，属**面向使用者的合规口径**，
须由指挥部与主席裁定后同步本文件与 `verify_matrix.py`。

## 通用规则：结论必须与同一行的参数一一对应

★ **若一行的参数已被更正，而结论来自旧参数下的跑次 ⇒ 该结论作废，该档标「尚未验证」；
仅在参数冻定后重跑，才可给出「已验证可用 / 已验证不可用」判定。**

- 落地：跑次结论携带「结论有效性注记」（数据字段 `conclusion_annotation`，`conclusion_valid: false` + 作废理由 + 参考记录）；
- 生成器处理：`build_official.py` 见 `conclusion_valid: false` ⇒ **状态回落为「尚未验证」**，并把旧跑次事实写入**备注**，
  显式标注"不对应当前行参数 ⇒ 判定作废、不作为该档可用/不可用判定"（⛔ 事实不丢，但**不得用作判定**）；
- 用词：`尚未验证` 等同 **未测试**；宪法 §17.7 的固定取值为「尚未验证」，用词以它为准。
