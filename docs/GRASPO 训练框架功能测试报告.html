1. 这是什么表

  • 这是 GRASPO 训练框架的功能测试基准（蓝图），包括测试方法、测试条件与测试结果。
  • 测试结果基于我们的多模态测试数据集，不保证在您的数据集上也能达到同样效果。

2. 测试方法

原则：训练之后效果变好，才算「可用」。

下面四条是判定依据：第 4 章「是否通过」列按这四条合取判定，未满足项写入备注。

  1. ① 能完整跑完：训练正常结束、无中断、无报错、退出码 0、优化器步数达到该档总训练步数（总训练步数 = 总训练轮数 × 每 epoch 步数，每 epoch 步数 = ⌈训练样本数 ÷ 总卡数⌉；本矩阵各档训练样本数统一为 100 条）、最终检查点完整可加载、没有 NaN/Inf。
  2. ② 效果变好（核心判据）：在平台方测试数据集与测试参数下，训练之后模型效果变好（CPT 判不劣化、允许与未训练模型持平；训练数据集即评测集（同一份 100 条）、vLLM 贪心温度 0、每档评一次；逐算法通过线见下）：
    • SFT（监督微调）：训练后数据集完全正确率（= 与参考答案逐字段完全一致的样本数 ÷ 100）提升至少 10.0 个百分点，判据 after − base ≥ +10.0 pp
    • GRASPO（强化）：训练后数据集完全正确率提升至少 5.0 个百分点，判据 after − base ≥ +5.0 pp
    • CPT（继续预训练）：训练 loss 正常下降、训练数据集准确率不下降，判据 after ≥ base（不劣化）；允许 after == base
    • OPD（蒸馏）：教师在训练数据集上的完全正确率，与学生未训练模型相比 ≥ +10.0 个百分点（教师 − 学生未训练模型 ≥ +10.0 pp）；学生训练后，训练数据集完全正确率提升至少 5.0 个百分点，判据 after − base ≥ +5.0 pp
  3. ③ 算法正确性检查通过：SFT / CPT / OPD 按各自公开的标准实现逻辑判断；GRASPO 按《GRASPO 算法说明》逐条判断（算法逻辑严禁改动）。SFT / CPT / OPD 另按公开标准核对损失函数与标签掩码的处理规则（OPD 另含教师信号的处理规则）。
  4. ④ 能推理：LoRA 档合并后、全参档直接，用 vLLM 启动，在训练数据集上完整推理一遍，能完整产出可解析的推理结果（效果是否变好由判据② 判定，本条只判能否推理）。

3. 测试条件

条件说明

数据集说明

  • 训练数据：平台方自有、不公开的多模态训练集（图像 + 文本）；从 V5 语料中随机采样 100 条作为训练语料，全部档位共用同一份。
  • 评测集与训练集相同（即上述同一份 100 条）。本测试不关注泛化性能，只关注训练框架本身的训练效果和正确性。

模型说明

  • 基础模型：Qwen3.5-9B、Qwen3.8-27B。
  • OPD 教师：Qwen3.8-27B 在 SFT / LoRA / dp=1 这一档训练完成后的产物（不是基座权重本身）。

LoRA 说明

  • 更新的是哪几块权重：两个后端的目标都是模型自身的线性投影权重，共四类 —— 语言主干每层的注意力投影（q_proj／k_proj／v_proj／o_proj）、线性注意力层的输入输出投影（in_proj_qkv／in_proj_z／out_proj）、每层 MLP 的三个线性层（gate_proj／up_proj／down_proj），以及视觉侧 merger 与每个视觉块的注意力／MLP 线性层；其余权重（词嵌入、各类归一化、卷积等）保持原值。
  • 目标写法（两个后端统一）：lora.target_modules 是一条真实 HF 模块名正则，一条表达式同时覆盖语言侧与视觉侧；两个后端都按这同一条正则确定更新哪些权重（ms-swift 走官方 --target_regex）。
  • 两个后端完全一致：更新的权重矩阵清单相同，且对每个权重矩阵施加一份低秩更新（融合的 Q／K／V 投影按整块处理）；r／alpha／dropout 也相同。
  • LoRA 参数（仅 LoRA 适用）：
    • LoRA rank r：32
    • LoRA alpha：64
    • LoRA dropout：0.05
  • 以本表取值为准：r = 32、alpha = 64、dropout = 0.05。

训练集群

  • A800，单机 8 卡，机器拓扑为 A800 PCIe：GPU 以 NVLink 成对相连、对与对之间走 PCIe bridge。

后端独有参数

下面这些参数在每个后端的所有档位上都取同一个值，因此只在这里说一次，第 4 章矩阵不再逐档重复。

ms-swift

  • 每卡批大小 per_device_train_batch_size=1
  • 序列并行 sequence_parallel_size=1：ms-swift 只做纯数据并行（tp 恒为 1），故 SP 恒关闭
  • 采样后端 use_vllm=false（不走 vLLM 采样）
  • 进程数 nproc_per_node=总卡数（只做纯数据并行）
  • LoRA 档在数据并行下不做参数分片：基座权重与适配器在每张卡上各存一份完整副本，优化器态只算适配器。
  • 全参档必须分片优化器态 ⇒ 走 FSDP2

native

  • 每卡批大小 micro_batch_size=1
  • 序列并行 sequence_parallel：tp_size>1 时开启，且 SP 尺寸 = tp_size；tp_size=1 时关闭（该能力要求 tp_size≥2）
  • 并行形状（按模式分列）：全参档：tp_size、dp_size 固定为 1，pp_size 可大于 1；LoRA 档：tp_size、pp_size、dp_size 均可大于 1（具体形状见第 4 章）
  • 1 卡全参必须开优化器态 offload（offload_optimizer_state=true），否则装不下
  • pp_size>1 且算法是 GRASPO 时，须显式开 allow_unverified_pp_rollout=true（默认拒绝启动）
  • CPT / OPD 没有 native 通道：这两个训练方法只能走 ms-swift

序列并行（SP）如何随 TP 一起测

  • SP 是 TP 的省显存子开关：把非 TP 区的激活沿序列维切给各 TP rank，通信换成 reduce-scatter / all-gather。
  • 规则：凡 tp>1 的档位一律开启 SP，且 SP 尺寸 = TP 尺寸；tp=1 的档位 SP 无意义，保持关闭。
  • 因为 SP 尺寸由 TP 尺寸派生，它不引入新的档位：矩阵里每加一维档位数翻倍，SP 搭 TP 的车测掉即可。
