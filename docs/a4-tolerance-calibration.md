## 1. A4 判据的四个子检查（先分清谁在管什么）

> ⛔ **以下全部为历史口径**（A4 容差体系已整体作废，见文首）：仅作方法论留痕，
> ⛔ 不得作为现行判据引用；现行判据见 `docs/capability-matrix.data.json`。

`judge_a4` 有四条**并列**子检查，任何一条不满足都判 A4 不通过：

| # | 子检查 | 口径 | 能否用容差放宽 |
|---|---|---|---|
| ① | **首步 loss 零容差**：两跑 `losses[0]` 逐位相同 | 零容差 | **绝对不可以**（红线） |
| ② | **终态 loss 容差**：`|L1 − L2| ≤ 档族容差` | 按档族标定，见本文 | 只按本文公式定，不得手调 |
| ③ | **符号翻转**：两跑终态 loss 异号且幅度超容差量级 | 真 bug 指纹（T032） | 不可以 |
| ④ | **独立通道**：末步权重 sha256 与 loss 通道冲突 ⇒ 不可判定 | 双通道一致 | 不可以 |

**为什么①是唯一有鉴别力的尺子**：首步 loss 只取决于**种子 / 初始化 / 数据顺序 / 首批样本**
——全是可控因素。已观测的真 bug 首步差全部 ≤ 3.3e-3，**小于任何合理的终态容差**，
所以终态容差一条都抓不到，只有①能抓。**①的实现与调用点不得改动**（有回归守卫测试）。

## 2. 档族键：五维

```
backend × cards × algorithm × model × mode
```

- `model` / `mode` 为 `None` 的标定行是**通配行**：覆盖全部 model/mode，只允许两类用途——
  ① 2026-09-22 之前的历史行（当时键只有三维，属**已登记债**）；
  ② 经"上包络"标定、确有证据覆盖全部 model/mode 的行。
- 为什么必须扩维：实测同族 `ms-swift/1/CPT` 的 9B 档差 `8.7e-3`、27B 档差 `4.14e-2`
  （**4.7×**）；`ms-swift/2/CPT` 9B `2.5e-3` vs 27B `4.35e-2`（**17.5×**）。单一容差被迫取
  大者、贴近硬上界，会把 9B 档的隔离带吃光。
- **维度未知时只允许命中通配行**（fail-closed，不得用某个精确 model 的行充数）。
- **算法名归一**：清单写 `GRASPO`、标定表写 `GRPO`（同一机制：GRPO trainer + graspo reward），
  由 `normalize_a4_algorithm` 做**显式精确**映射 `{"GRASPO": "GRPO"}`。不做大小写归一、
  不做前缀匹配、不猜——未登记的算法串原样比较，未命中即 fail-closed。

## 3. 容差公式

```
tol = max( min( 1.5 × worst_pair,  4.675e-2 ),  1.0302e-3 )
```

| 量 | 值 | 含义 |
|---|---|---|
| `worst_pair` | 读数池的 `max|L_i − L_j|` | 取自**同档族 n≥5 次独立重复跑**的终态读数池 |
| `A4_WORST_PAIR_SAFETY_FACTOR` | `1.5` | **人工判断常数**（见 §5） |
| `A4_TOLERANCE_HARD_UPPER_BOUND` | `4.675e-2` | **锁一**：任何档族容差 ≤ 最小真 bug 签名 / 2 |
| `A4_MIN_TRUE_BUG_SIGNATURE` | `9.35e-2` | T032 的**符号翻转**实测签名（−0.0217 → +0.0718） |
| 基线下界 `A4_MEASURED_BF16_FINAL_LOSS_DRIFT` | `1.0302e-3` | 2026-09-19 T013 单档实测；**只作下界**，不再全局化 |
| `A4_CALIBRATION_MIN_N` | `5` | n<5 不得定档（只标"证据不足" + 下界） |

**隔离带**：`9.35e-2 / tol > 2.0×`（模块导入时断言）。隔离带 = 2.00× 表示该族终态判据
只剩底线鉴别力，必须在台账显式标注。

### 三条防循环论证的硬约束（这是"正确"的核心）

1. **M1 池与被判对互斥**：定容差用的 n≥5 跑，**不得包含**即将被该容差判定的那两跑。
   否则"判定的差 ≤ 池内最坏对"由构造恒成立 ⇒ 判据必然通过，与训练是否真可复现无关。
   `scripts/a4_calibrate.py` 对违反 M1 的输入**当场拒绝**（⛔ 该脚本已退役，此为其
   历史行为口径；现行流程不再执行标定）。
2. **M2 上界来自池外独立事实**：`tol×2 < 9.35e-2` 这条锁用的是 T032 的实测签名，
   **不来自本族漂移数据**，因此无法被本族数据"喂大"。
3. **M3 规则先固定、后采数**：公式、倍数、`min_n`、封顶、卡集纪律在采数**前**写死；
   采数后只允许按公式代入，**不允许看结果调倍数或调容差**（那是放宽，不是标定）。

## 4. 可标定性门：只在"漂移确属 §6 排除项"时才允许定容差

宪法 §6 把"GPU 内核选择等**无法控制**的差异"排除在"复现破坏"之外 —— 容差**只**为这类
差异而设。一旦证据指向"**可控而未控**"，必须转根因，**不许用容差盖**。

| 门 | 判据 | 不通过 ⇒ |
|---|---|---|
| **G1 首步/输入门** | 两跑首步 loss 逐位相同；ms-swift 档还应核 `input_ids_sha256` 四通道一致 | 可控未控 ⇒ 转根因，不定容差 |
| **G2 退化门** | 末步是有效训练步（`loss≠0`、`len(losses)≥2`） | 终态通道零鉴别力 ⇒ 只能标 `degenerate` |
| **G3 形态门** | n≥5 池单峰、簇间隙相对 `worst_pair` 小 | 双峰/离散分支 ⇒ 转根因 |
| **G4 隔离带门** | `tol×2 < 9.35e-2` | 只剩底线鉴别力，台账显式标注 |
| **G5 独立性门** | n 跑各自完整 runner 进程 + 各自 `RUN_ROOT` + 同清单 sha + **同卡集** + 同镜像 + 同代码 HEAD | 复用/自比 ⇒ 该批作废 |

**卡集纪律（AO1 实测依据）**：`T032` 在卡集 `{4,5}` 上 n=5 最坏对 `4.0139e-3`；
并入 `{0,1}` 的两次后最坏对抬到 `1.1014e-2`（**方差 ≈2.74×**），隔离带从 15.53× 掉到 5.66×。
⇒ 读数池与被判双跑**必须同卡集合**；跨卡集的数据不得并入。

**4 卡 GRPO/OPD 的特别警告（🔴）**：实测证据（`task-ap1-locate-op` / `task-at1-bimodal` /
`task-an1-determinism-complete` / `task-au1-layerwise`）把 4 卡 GRPO 的残余定位到
**可指名的可控未控算子**（torch flash 反向 `attention_backward.cu`；`model.layers.1.linear_attn`
前向多值），**不属 §6 排除项**。因此：**先修确定性（如 `attn_implementation: eager` 或
`torch.use_deterministic_algorithms(True)`）、用 G1 复验 n≥5 首步逐位一致，再校准**；
且**校准池与被判配置必须逐字一致**（否则容差不可用）。

## 5. 诚实的统计限度（必须照写，不许拔高）

- **n=5 不是统计意义上的容差上界**。分布无关的单侧容差区间（95% 覆盖 / 90% 置信）
  需要 `n = ln(0.10)/ln(0.95) ≈ 45` 个样本；n=5 的最坏对只覆盖 95% 分布 77.4% 的置信度。
- **`1.5×` 是工程安全余量（人工判断常数）**，不是从分布推出的分位数。它的作用是补
  "n=5 的 max 是重尾分布的弱估计量"这个小样本低估偏差。
- n≥5 的**下限**依据：AD1 §7.2 实测 T010 的 `n=2` 最坏对 0.0044 vs 全池 n=5 的 0.0344，
  **低估 7.8×**；分布形态是**重尾/双峰**（两簇相距 ~0.03），不是正态 ⇒ 均值+σ 不可用。
- 对观测差接近硬上界的族（如 27B CPT），建议 `n = 7–10` 以判断尾部是否饱和。

## 6. 可追溯性要求（§1.4 单一真相源）

每条 `A4TierCalibration` 记录都必须能指回它的数据来源与样本量。**`calibrated` 行**强制：
`provenance` / `representative_tier` / `model_scope` / `sampled_at` / `split_check` **全非空**，
且 `n ≥ 5`、`worst_pair > 0`——由 `validate_tier_calibration_entry` 在**模块导入时**校验
（表被改坏 ⇒ 启动即失败，而不是等到某一档跑完才发现判据失去隔离带）。

`provenance` 必须逐字写出：逐跑读数、清单 sha256、卡集、`RUN_ROOT` 独立性证据、公式代入、
采样日期、出处工位路径、入表裁定来源。参考已有范本：`ms-swift/2卡/GRPO` 行。

## 7. 怎么新增一个档族（操作手册）

1. 用既有双跑证据先过 **G1/G2**（这两条不需额外 GPU）。
2. 写池规格 JSON（字段见下），跑：

   **⛔ 下列脚本已退役（历史用法，不可执行）：**

   ```bash
   python3 scripts/a4_calibrate.py --input pool.json --out entry.py
   ```

   脚本会：校验 M1 / 独立性 / 卡集 → 按公式推导 → 当场过 `validate_tier_calibration_entry`
   → 打印**逐字可粘贴**的 `A4TierCalibration(...)` 元组。**输入里没有"容差"字段**——
   容差只能由公式推导，从源头堵住"看结果调容差"。
3. 把元组粘贴进 `A4_TIER_CALIBRATIONS`；模块导入时会再校验一次。
4. 补一条测试断言（取值 + 隔离带 + `provenance` 非空）。

池规格 JSON 的必填字段：`backend` / `cards` / `algorithm` / `model` / `mode` /
`representative_tier` / `card_set` / `sampled_at` / `split_check` / `provenance` /
`run_roots` / `readings`（可选 `judged_pair`：`{run_roots, delta}` 用于 M1 核对 + 预判）。

**三条必读结论**：

1. **model 分维是必需的**：ms-swift/1/CPT 的 9B 池 tol 1.53e-2（隔离带 6.13×），27B 池 4.87e-2
   ⇒ 封顶 4.675e-2（2.00×）。若沿用三维键，9B 会被 27B 拖到封顶——J2/P1 的价值在数据上成立。
2. **n=5 会低估重尾**：ms-swift/1/CPT 9B 的 n=5 池最坏对 2.98e-3，而**互斥的** judged pair 差
   8.74e-3（2.9×）⇒ 按预先写明的规则扩到 n=10，worst_pair 升到 1.017e-2、tol 1.53e-2
   （被判差落回容差内）。**这是诚实扩样，不是调容差**；扩样触发条件是"互斥的 judged pair
   落在池外"，与容差取值无关。
3. **可标定性门真的拦住了东西**：ms-swift/1/OPD 9B 与 ms-swift/2/GRASPO 27B 都出现
   "同配置、同子集 sha、首步 loss 却不同"（1/5 跑）——即 §4 警告的"可控未控"形态，
   **在 2 卡/1 卡上也会出现**（不限于 4 卡）。它们保持 fail-closed 并转根因调查。

## 10. A4 的角色与边界（2026-09-22 用户裁决后）

### 10.1 角色：**诊断，不是门槛**

- 用户 2026-09-22 的口径原话（本节是该口径的落档）：
  > "你的判定标准应该是**能顺利跑完一个 epoch**，怎么搞这么复杂？
  > 我们现在看的**不是效果，是训练可用**。"
- ⇒ **A4（同 config 同 seed 双跑一致）从门禁降级为诊断字段**。它**仍被计算、仍写入台账**
  （`criteria.A4` + `criteria_detail.A4`，含容差、档族、样本量、最坏对），
  但**不参与"这一档能不能用"的判定**。
- **主判据 = 能顺利跑完一个 epoch**（判定器总判定的改造由对应工作包负责；本文件只登记口径，
  不自行改门禁语义）。
