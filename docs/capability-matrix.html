2. 测试方法

原则：训练之后效果变好，才算「可用」。

  1. 能完整跑完：训练正常结束、无中断、无报错、退出码 0、优化器步数达标、检查点完整、没有 NaN/Inf。
  2. 效果变好（核心判据）：在平台方测试数据集与测试参数下，训练之后模型效果比不训练的原始模型好（逐算法通过线见下）：
    • SFT（监督微调）：训练后数据集完全正确率提升至少 10.0 个百分点，判据 after − base ≥ +10.0 pp
    • GRASPO（强化）：训练后数据集完全正确率提升至少 5.0 个百分点，判据 after − base ≥ +5.0 pp
    • CPT（继续预训练）：训练 loss 正常下降、训练数据集准确率不下降，判据 after ≥ base（不劣化）
    • OPD（蒸馏）：教师在训练数据集上的完全正确率，高于学生未训练模型 10 个百分点，学生训练后，训练数据集完全正确率提升至少 5.0 个百分点，判据 after − base ≥ +5.0 pp
  3. 算法正确性检查通过：各算法按自己的检查清单逐项通过，确认该算法的机制真实生效、实现正确（SFT / GRASPO / CPT / OPD 各按自己的清单）；GRASPO 的算法逻辑严禁改动。
  4. 能推理：合并 LoRA 后用 vLLM 启动，训练数据集可以完整推理一遍，效果好于未训练模型。

3. 测试条件

条件说明

数据集说明

  • 训练数据：平台方自有、不公开的多模态训练集（图像 + 文本）。
  • 评测集与训练集相同。本测试不关注泛化性能，只关注训练框架本身的训练效果和正确性。

模型说明

  • 基础模型：Qwen3.5-9B、Qwen3.8-27B。
  • OPD 教师：Qwen3.8-27B。

LoRA 说明

  • native：配置里 lora.target_modules 声明的是两个 preset 名 —— language_all_linear、vision_common（preset 名不是层名、不是模块名单），由本仓解析器按规范目标名逐 pattern 匹配（glob，* 可跨 .）后展开为三组：full_attn 的 q_proj／k_proj／v_proj／o_proj、linear_attn 的 q_proj／k_proj／v_proj／in_proj_z／out_proj、mlp 的 gate_proj／up_proj／down_proj；视觉 —— merger.linear_fc1／merger.linear_fc2 ＋ blocks.attn.qkv／attn.proj／mlp.linear_fc1／mlp.linear_fc2。
  • ms-swift：配置里 lora.target_modules 是一条真实 HF 模块名正则（覆盖 language_model 侧与视觉侧 blocks／merger 的 Linear），本仓按官方 --target_regex 下发；不展开成逐层名单（仓内无逐层名单，只有实测计数）。
  • 两后端不等价：命中的模块集合不同（native 落在内部键名 token_mixer.*，ms-swift 落在 language_model.layers.N.linear_attn.*／self_attn.*）⇒ 跨后端的效果／性能读数不直接可比，跨后端比较必须注明。
  • Qwen3.8-27B 的生效层（已核实）：与 9B 同族，但为 64 层（linear_attn 48 层 ＋ full_attn 16 层；9B 为 32 层 ＝ 24 ＋ 8），视觉侧深度同为 27。两条后端都命中注意力层，不存在「注意力层整类不命中」：preset 的 pattern 形如 language.*.q_proj（* 可跨 .），匹配对象是规范目标名（language.full_attn.*／language.linear_attn.*），由模型族与视觉深度生成，与真实模块命名无关；full_attn 只是本仓的规范目标名，两个基础模型在 HF 侧的真实模块名都是 self_attn。按层展开：native 的 27B ＝ 语言 496 个实例（full_attn 4×16 ＋ linear_attn 5×48 ＋ mlp 3×64）＋ 视觉 110；ms-swift 正则实测覆盖 27B 语言侧 496 条真实模块（self_attn 的 q_proj／k_proj／v_proj／o_proj，linear_attn 的 in_proj_qkv／in_proj_z／in_proj_a／in_proj_b／out_proj，mlp 的 gate_proj／up_proj／down_proj）＋ 视觉 110。两者实例数相同，但真实模块集合不同：ms-swift 多覆盖 in_proj_a／in_proj_b（各 48 条），native 的 linear_attn q_proj／k_proj／v_proj 三条落在同一个真实模块 in_proj_qkv 上 ⇒ 可训练参数量不同。视觉侧逐条清单与 9B 相同（同一代码路径 ＋ 同一深度 27；9B 侧有实测清单，27B 侧为同路径推断）；27B 的可训练参数量未核实。
  • LoRA 参数（仅 LoRA 适用）：
    • LoRA rank r：32
    • LoRA alpha：64
    • LoRA dropout：0.05

训练集群

  • A800，单机 8 卡，机器拓扑为 A800 PCIe：GPU 以 NVLink 成对相连、对与对之间走 PCIe bridge。

统一超参（对所有档位相同）

  • 上下文长度上限（token）：8192
  • 权重精度：bfloat16
  • 梯度检查点：true
  • 单卡 micro batch size（native：micro_batch_size／ms-swift：per_device_train_batch_size）：1
  • 梯度累积 micro-batches：1
  • 每轮保存检查点（训练过程控制，训练循环直接消费）：false
  • GRASPO 奖励类型：graspo
  • 序列并行度（只对 ms-swift 档生效）：1
  • ms-swift 档是否用 vLLM 推理（只对 ms-swift 档生效）：false
  • 运行期显存监控采样间隔（秒）：2.0
  • 训练随机种子：42
