## 3. 功能矩阵：算法 / 模式 / 后端

### 3.1 需求口径与用户已拍板范围

本产品的需求是**"能用哪些分片与降显存方法"**，不是"支持多少个底层训练框架"。**方法才是需求**（TP / PP / CP / SP / 各类分片 / offload / l2k / packing / padding_free / GC / GA …），**框架只是手段**——按"哪套能把方法做得最好"来选。**对外只有 `native` / `ms-swift` 两档后端**；引擎 / 路径选择是 `ms-swift` 后端的**内部实现策略，不暴露给用户做选择**；因此 §4 的表**按"方法"分行**。

**用户已拍板的范围**（硬性）：`27B × 全量`不做｜`CPT` `OPD` 仅 ms-swift、**LoRA 与全量均支持**｜`CP` 不加 native｜8 卡不做｜native 目标 = 并行 DP / TP / PP / SP，算法 SFT / GRASPO｜**多模态是所有训练的目标**。

## 4. 功能矩阵：分片与降显存方法（五层）

这五层按"在配置里解决什么问题"划分；**哪些选项能同时开、哪些互斥**见每层末尾的硬约束。

### 层 1 · 并行维度（世界大小如何切分）

| 项 | 作用 | native 目标 | native 当前 | ms-swift 目标 | ms-swift 当前 |
|---|---|---|---|---|---|
| **DP**（数据并行） | 把数据切到多卡；复制模型 | **目标** | ✅ 可用 | **目标** | ✅ 可用 |
| **TP**（张量并行） | 把权重的 hidden / 头 / FFN 中间维切到多卡。native 须整除注意力头数，且并行度不超过 KV 头数 | **目标** | ✅ 可用 | **目标**（依托 Megatron 引擎） | ⚠️ 未验证【注册层证据，运行时未验证】 |
| **PP**（流水线并行） | 把层切到多卡，多段流水。native 当前仅一种流水调度，且多卡实测曾失败 | **目标** | ⚠️ 未验证【实测】 | **目标**（依托 Megatron 引擎） | ⚠️ 未验证【注册层证据，运行时未验证】 |
| **SP**（序列并行） | **沿序列维**切激活，长上下文的关键手段之一。**注意：本仓库有三套 SP 机制，不可混用**——按机制名区分：native 布尔开关、ms-swift 标准路径整数度、Megatron 段布尔开关 | **目标** | ✅ 可用 | **目标** | 标准路径 ✅ 可用｜Megatron 段 ⚠️ 未验证【注册层证据，运行时未验证】 |
| **CP**（上下文并行） | **沿序列维**切分，**只切序列、不切权重**；唯一能覆盖 CP 的是 Megatron 引擎（用户已定 native 不做 CP）。**⛔ 目标模型下 CP 不可用【源码级证据，未实测】** | **不做**（用户已定） | ⛔ 不支持 | **目标**（依赖 Megatron 引擎） | ⛔ 不支持（上游阻断） |
| **按层切分** | 按层把模型切到多卡；它决定卡上放什么，属并行维度 | **不做**（用户已定） | ⛔ 不支持 | ⛔ 本期不做（按需补充） | ✅ 可用 |
| **AutoTP**（自动张量并行） | 自动张量并行（上游仅全参）；是对 TP 的自动化，属并行维度 | **不做**（用户已定） | ⛔ 不支持 | 待定（全量入口打通后评估） | ⚠️ 未验证【源码级证据，未实测】 |

**层内硬约束**：native——`TP × PP × DP = 卡数`，不匹配即报错，且 SP 不占卡、与 TP 同进程组、**须 `TP ≥ 2`**；ms-swift——SP 是独立轴，其并行度须整除 KV 头数，DP 度 = 卡数 ÷ SP 度，**与 native 不是同一条恒等式**。

### 层 2 · 分片策略（权重 / 梯度 / 优化器状态如何摊）

| 项 | 作用 | native 目标 | native 当前 | ms-swift 目标 | ms-swift 当前 |
|---|---|---|---|---|---|
| **优化器态 / 梯度分片**（ZeRO-1/2 等价物） | 把优化器态与梯度摊到各卡；Megatron 侧的分布式优化器是其原生能力 | **不做**（用户已定） | ⛔ 不支持 | **目标**（优先 Megatron 分布式优化器） | ✅ 可用 |
| **权重分片 / CPU offload / FSDP2** | 把权重也摊到各卡；把优化器态与权重换出到 CPU 内存；全分片数据并行（v2，补充路径） | **不做**（用户已定） | ⛔ 不支持 | **目标**（Megatron-FSDP / ZeRO-3 / ZeRO-3 offload 预设） | ✅ 可用 |

**层内硬约束**：在**同一世界大小内**把常驻状态再摊开，**不改变卡的分配方式**；路线为优先用 Megatron 引擎的分布式优化器与参数 / 梯度分片，DeepSpeed 与 FSDP2 作补充。**DeepSpeed / FSDP2 / 按层切分三者互斥**。**Megatron 路径三条硬约束**（上游规定）：① **LoRA 必须走 mcore-bridge 桥接**（另一座桥不支持 LoRA，非全参时直接报错）；② 只训语言模型（不含视觉）时**不能用另一套 LoRA 实现**；③ **视觉冻结默认开启，且该冻结逻辑仅对全参生效**——即 LoRA 模式下视觉塔不会被冻结逻辑覆盖。

### 层 3 · 激活与 logits 削峰（不改卡数分配，只降峰值）

| 项 | 作用 | native 目标 | native 当前 | ms-swift 目标 | ms-swift 当前 |
|---|---|---|---|---|---|
| **GC / 激活重算** | 用激活重算换显存；native 默认开启 | **目标** | ✅ 可用 | **目标**（Megatron 引擎下缺配置入口，待补映射） | ⚠️ 未验证【源码级证据，未实测】 |
| **l2k** | 只对少量 token 计算输出层，省 logits 及其梯度 | **不做**（用户已定） | ⛔ 不支持 | **目标** | ✅ 可用 |
| **FA2**（flash attention） | 更省显存的注意力实现；是 SP / packing 的硬前置。native 侧为可选实现，未在 native 上验证 | **不做**（用户已定） | ⚠️ 未验证【源码级证据，未实测】 | **目标** | ✅ 可用 |

### 层 4 · 批次与序列组织（一次算多少、样本怎么拼）

| 项 | 作用 | native 目标 | native 当前 | ms-swift 目标 | ms-swift 当前 |
|---|---|---|---|---|---|
| **micro-batch size** | 单次前向的样本数 | **目标** | ✅ 可用 | **目标** | ✅ 可用 |
| **梯度累积（GA）** | 多步累积再更新，放大有效 batch | **目标** | ✅ 可用 | **目标** | ✅ 可用 |
| **packing** | 把多条短样本拼进同一序列，减少 padding 浪费；开启后自动置 padding_free，进而强制 flash attention | **不做**（用户已定） | ⛔ 不支持 | **目标** | ✅ 可用 |
| **padding_free** | 免 padding 的变长批处理 | **不做**（用户已定） | ⛔ 不支持 | **目标** | ✅ 可用 |

## 5. 长上下文能力

**长上下文必须有序列维分片，否则 OOM 风险极高。**

- **序列维分片** = 把一条长序列按 token 维切开、摊到多卡。**只有 SP / CP 属于这一类**；**DP / TP / PP 都不切序列维**——加卡但不切序列，长序列的单卡占用不会下降。
- **native 可用手段 = SP**（与 TP 同进程组，须 `TP ≥ 2`，不额外占卡）。
- **CP 是本期目标**，须依托 ms-swift 的 Megatron 引擎；**⛔ 目标模型的 CP 已确认不可用【源码级证据，未实测】**——上游两个层面阻断：其一，所用内核版本内**不存在混合线性注意力（GDN）的 CP 实现**；其二，下游桥接包在**模型构建阶段**断言 CP 度必须为 1，CP > 1 直接失败。**本次未实测 CP = 2**。
- **回退路径（即本期实际路径）= ms-swift 标准路径的 SP + ZeRO-3**；native 侧 = SP + TP / PP。依据摘要：**因目标模型的 CP 被上游限制为 1，Megatron 路径的 SP 度直接取自 CP 值，同样被锁定为 1，不能作为序列维分片的回退【源码级证据，未实测】**；可用的回退是 ms-swift **标准路径**的 SP（另一套机制，不受 CP 限制）。
- ⇒ 本节只规定"**必须靠什么机制**"；**每档实际能到多长由实测得出**，不由本文档推断。
